    Stabilization handoff — 3 November 2026

    The starting revision is 466b1bcc4d4d99209dea8522dd6a14aa43bf4168. The stabilization changes are submitted for review; release and package publication remain separate work.

    Changes

    • Pin Pixi 0.82.1 in the manifest and CI. Map conda ray-core only to PyPI ray: the previous hash mapping also claimed bundled packages such as aiohttp at Ray's version, invalidating the lockfile whenever it was checked.
    • Run ROS 2 CI in the official Humble/Jammy and Jazzy/Noble ROS base images, retaining both build/test jobs. This removes the setup action's unauthenticated latest-release lookup and ROS repository-package download, which failed with HTTP 404 before the Humble build. The images already provide ROS, colcon and rosdep; dependency installation still runs for the repository's package manifests.
    • Retry transient full-dataset download failures up to three times. CI uses a checked-in, hash-verified archive of the exact original seed-1 selection to avoid the GitLab outage on cold runs. The smoke gate still requires the same 20 scenarios across four planners (80 result rows), with no evaluation errors. Scenario provenance and the retained upstream license accompany the archive.
    • Keep base profile tests independent of CommonRoad and run the optional integration test explicitly in CommonRoad CI. All four profiles are checked in installed wheels.
    • Recheck oncoming clearance until the measured footprint leaves the lane, including when stitching projects a future departure. Remember the blockers of a committed pass, discard that state on return/reset/map replacement, and require fresh clearance for a different blockage. After passing the blockers, retain oncoming access until the measured footprint has merged back, while reopening the home lane for that return. Collision checking remains active.
    • Exercise parking recovery through LocalPlanner: entry, blocked exit, yielding to moving traffic, resumption and handover. These tests use deterministic synthetic maps.
    • Run Bench2Drive routes under a Linux child subreaper, including detached CARLA sessions. Finished driving failures remain valid results; incomplete checkpoints retry once. Attempt logs and incomplete directories are retained, with archives outside the directory scanned by the result summarizer.

    Remaining benchmark work

    The completed 30-trial Bench2Drive study used 42 validation routes in a separate fiss_tune checkout. Its best tuning Driving Score was 75.41 (base 69.28); those are tuning scores. The candidate record retains parameters and provenance. No code revision or independent check split was recorded, so it has not replaced the shipped profile.

    Passing-state continuity assumes stable obstacle IDs. Permission is not a collision-free guarantee: trajectory validation may still hold or brake for traffic. The synthetic recovery tests and two focused CARLA routes do not establish general Bench2Drive success. Full tuning, held-out Bench2Drive/nuPlan evaluation and release preparation remain separate work.

Its trace shows repeated near-zero-speed plans while pass_blocked is active. This remains a sampling/cost/profile investigation; the passing-state fixes do not establish that this scenario is solved.
